# 画面デザイン定義書

## 1. 目的

本書は、RoadRide Sharing MVPの画面デザインを統一し、利用者と運転手が迷わず操作できるUIを定義する。

利用者画面は「大きく、簡単に、安心して操作できること」を重視する。運転手画面は「停車中に一目で確認でき、少ない操作で記録できること」を重視する。

## 2. デザイン方針

- 利用者画面は入力項目と操作数を必要最小限にする。
- 配車候補は数を絞り、時刻・料金・待ち時間の違いを並べて比較しやすくする。
- 運転手画面は次の便の情報を最上部に置き、主要操作を大きなボタン1つに絞る。
- 稼働中の区分（利用者・運転手）を常にヘッダーに表示する。
- 同じ種類のボタン、入力欄、状態表示は全画面で同じ見た目にする。
- 色だけで意味を伝えず、必ず文字やアイコンを併用する。
- 予約登録、配車確定、キャンセル、運行開始、乗車完了などの重要操作には確認画面を設ける。
- 入力エラーは該当項目の近くに日本語で表示する。
- AI候補には、候補になった理由と注意事項を表示する。

## 3. 画面構成

### 3.1 利用者画面

共通ヘッダーにサービス名、稼働中の区分、予約履歴へのリンクを表示する。

```text
[RoadRide]  利用者として利用中 [切り替え]          [予約履歴]

画面タイトル
説明文

入力欄または予約情報

エラー・注意メッセージ

[戻る]                              [次へ・登録・確定]
```

対象画面：

- 乗車予約画面
- 予約確認画面
- 予約完了画面
- 配車候補選択画面
- 予約詳細・キャンセル画面
- 予約履歴画面

### 3.2 運転手画面

共通ヘッダーにサービス名、稼働中の区分、運行履歴へのリンクを表示する。車内での利用を想定し、スマートフォン縦向きを基本レイアウトとする。

```text
[RoadRide]  運転手として稼働中 [切り替え]          [運行履歴]

次の便
09:50 出発  電波学園前
乗客 2名（車いす 1名）

乗車順
1. 電波学園前   佐藤 由美 様  1名
2. ○○病院前    山田 太郎 様  1名 車いす

[          運行を開始する          ]
```

対象画面：

- 運転手ホーム・担当運行一覧
- 運行詳細・状態更新画面
- 運行履歴画面

### 3.3 アカウント・稼働区分切り替え画面

登録済みの区分と、現在稼働中の区分を表示する。切り替えられない場合は、ボタンを無効にし、理由（未完了の予約・運行がある）をボタンの近くに表示する。

## 4. デザイン仕様

### 4.1 色

| 用途 | 色 | 用途 |
| --- | --- | --- |
| メインカラー | `#1D4ED8` | 主要ボタン、リンク、選択状態 |
| 成功 | `#15803D` | 予約確定、乗車完了 |
| 注意 | `#B45309` | 待ち時間、確認が必要な状態 |
| エラー | `#B91C1C` | 入力エラー、定員超過、キャンセル |
| 情報 | `#0369A1` | マッチング中、案内メッセージ |
| 本文 | `#172033` | 通常の文章、見出し |
| 補助文字 | `#475569` | 説明文、補足情報 |
| 背景 | `#F8FAFC` | ページ背景 |
| 枠線 | `#CBD5E1` | 入力欄、区切り線 |
| 白 | `#FFFFFF` | パネル、入力欄、カード背景 |

背景色と文字色のコントラストを確保し、状態表示には色と文字を併用する。

### 4.2 文字

- 本文は16px以上とする。
- 見出しは24px前後とする。
- 画面タイトルは28pxを上限の目安とする。
- ボタン文字は16px以上とする。
- 行間は本文で1.6以上とする。
- 文字の詰めすぎを避け、letter-spacingは0とする。

### 4.3 レイアウト

- ページ全体の最大幅は1200pxとする。
- 利用者画面の本文幅は720px以内とする。
- PCでは左右に24px以上の余白を確保する。
- スマートフォンでは左右に16px以上の余白を確保する。
- 入力欄と主要ボタンは画面幅に合わせて伸縮させる。
- 情報カードを二重に入れ子にしない。
- 画面内の主要操作は1つに絞る。

### 4.4 ボタン

| 種類 | 用途 | 例 |
| --- | --- | --- |
| 主要ボタン | 画面の中心となる操作 | 予約を登録、この便に決める、運行を開始する |
| 通常ボタン | 補助操作 | 修正する、ほかの候補を見る |
| 危険ボタン | 取り消しや削除 | 予約をキャンセル |
| 戻るボタン | 前画面へ戻る | 戻る |

- ボタンの高さは48px以上とする。
- ボタンの文言は動作が分かる日本語にする。
- 重要操作は確認画面を表示してから実行する。
- ボタンを無効化する場合は、理由を近くに表示する。
- スマートフォンではボタンを横並びにしすぎない。

### 4.5 入力欄

- ラベルを入力欄の上に表示する。
- 必須項目には「必須」と表示する。
- 例示が必要な場合はプレースホルダーではなく補足文を使用する。
- エラーは入力欄の直下に表示する。
- 日時、人数、配慮事項には適切なHTML入力要素を使用する。
- 入力エラーがあっても、入力済みの値を消さない。

## 5. 予約状態の表示

| 状態 | 表示名 | 色 | 説明 |
| --- | --- | --- | --- |
| `matching` | マッチング中 | 情報色 | 配車候補の作成中、または便の選択待ち |
| `confirmed` | 予約確定 | 成功色 | 利用者が便を選び、確定済み |
| `in_progress` | 運行中 | メインカラー | 運行が開始されている |
| `completed` | 乗車完了 | 成功色 | 乗車・運行が完了 |
| `cancelled` | キャンセル | エラー色 | 予約が取り消されている |

状態は、色付きのバッジだけでなく、必ず表示名を記載する。

## 6. 利用者画面の定義

### 6.1 乗車予約画面

表示項目：

- 乗車場所
- 目的地
- 希望乗車日時
- 乗車人数
- 配慮事項

主操作：

- `予約内容を確認`

エラー例：

- 乗車場所を入力してください
- 目的地を入力してください
- 希望乗車日時を入力してください
- 乗車人数は1名以上で入力してください

### 6.2 予約確認画面

入力内容を読み取り専用で表示する。修正と登録を明確に分ける。

主操作：

- `内容を修正`
- `予約を登録`

### 6.3 予約完了画面

表示項目：

- 予約番号
- 予約状態
- 希望乗車日時
- 乗車場所
- 目的地
- 次に行う操作の案内（配車候補を選ぶ）

### 6.4 配車候補選択画面

候補は多くても3件程度に絞り、カードで縦に並べる。

各候補の表示項目：

- 乗車予定時刻
- 運転手名
- 料金目安
- 所要時間・待ち時間
- 相乗りの人数と空き
- マッチング理由（分かりやすい言葉で1文）

主操作：

- `この便に決める`（確認画面を挟んで確定する）

候補がない場合は、希望時刻や乗車場所を変更する案内を表示する。

### 6.5 予約詳細・キャンセル画面

`confirmed` の場合は、確定した乗車時刻、乗降場所、運転手名、料金目安、所要時間を表示する。

主操作：

- `予約をキャンセル`
- `予約履歴へ戻る`

### 6.6 予約履歴画面

予約を乗車日時の新しい順に表示する。各行またはカードには予約番号、日時、目的地、状態を表示する。

## 7. 運転手画面の定義

### 7.1 運転手ホーム・担当運行一覧

表示項目：

- 次の便（出発時刻、最初の乗車場所、乗客数、配慮事項の有無）
- 本日の担当運行一覧（出発時刻、状態）

`proposed` の便は表示しない。新しい便が確定したときは画面上で通知する。

### 7.2 運行詳細・状態更新画面

表示項目：

- グループ番号
- 車両
- 出発時刻
- 乗車順・降車順と乗降場所
- 乗客の氏名、人数、配慮事項
- 現在の状態

主操作（状態に応じて1つだけ表示する）：

- `confirmed` のとき: `運行を開始する`
- `in_progress` のとき: `乗車完了にする`

どちらも確認画面を挟み、誤操作を防ぐ。配慮事項は色と文字で目立たせる。

### 7.3 運行履歴画面

完了・キャンセルした便を新しい順に表示する。各行には運行日時、乗車場所、乗客数、状態を表示する。

## 8. 状態別の画面表示

### 読み込み中

- ボタンを連打できない状態にする。
- 「読み込み中」と表示する。
- 既存データがある場合は、可能な範囲で表示を維持する。

### データなし

- 「該当する予約はありません」のように具体的に表示する。
- 次にできる操作があればボタンを表示する。

### 通信エラー

- 「データを取得できませんでした」と表示する。
- `再試行` ボタンを表示する。
- 二重登録を避けるため、送信済みの登録操作を自動で再実行しない。

### 入力エラー

- エラー項目へ移動できるようにする。
- エラー文は日本語で具体的に表示する。
- 送信済みの入力値は保持する。

## 9. レスポンシブ対応

| 画面幅 | レイアウト |
| --- | --- |
| 767px以下 | 1列。一覧と詳細を縦に表示 |
| 768px以上 | 一覧と詳細を2列で表示 |
| 1200px以上 | 最大幅1200pxで中央寄せ |

スマートフォンでは横スクロールを発生させず、表形式の情報はカードまたは縦積みに切り替える。

## 10. 実装確認項目

- [ ] 全画面でヘッダーと余白のルールが統一されている
- [ ] 本文とボタンの文字が小さすぎない
- [ ] 状態が色と文字の両方で分かる
- [ ] 必須入力とエラー表示が分かる
- [ ] 重要操作に確認画面がある
- [ ] 読み込み中、データなし、通信エラーを表示できる
- [ ] PCとスマートフォンの両方で横スクロールが発生しない
- [ ] 利用者画面は予約から配車確定までを4画面以内で完了できる
- [ ] 運転手画面の主要操作が大きなボタン1つにまとまっている
- [ ] 稼働中の区分がヘッダーに表示され、切り替えできない理由が分かる
