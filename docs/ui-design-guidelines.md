# 画面デザイン定義書

## 1. 目的

本書は、RoadRide Sharing MVPの画面デザインを統一し、利用者と配車担当者が迷わず操作できるUIを定義する。

利用者画面は「大きく、簡単に、安心して操作できること」を重視する。配車担当者画面は「多くの予約情報を短時間で確認・操作できること」を重視する。

## 2. デザイン方針

- 利用者画面は入力項目と操作数を必要最小限にする。
- 配車担当者画面は一覧性と比較のしやすさを優先する。
- 同じ種類のボタン、入力欄、状態表示は全画面で同じ見た目にする。
- 色だけで意味を伝えず、必ず文字やアイコンを併用する。
- 予約登録、配車確定、キャンセルなどの重要操作には確認画面を設ける。
- 入力エラーは該当項目の近くに日本語で表示する。
- AI候補には、候補になった理由と注意事項を表示する。

## 3. 画面構成

### 3.1 利用者画面

共通ヘッダーにサービス名と予約履歴へのリンクを表示する。

```text
[RoadRide]                                      [予約履歴]

画面タイトル
説明文

入力欄または予約情報

エラー・注意メッセージ

[戻る]                              [次へ・登録・確定]
```

対象画面：

- 乗車予約画面
- 予約確認画面
- 予約完了・マッチング結果画面
- 予約詳細・キャンセル画面
- 予約履歴画面

### 3.2 配車担当者画面

共通ヘッダーにサービス名、画面切り替え、担当者情報を表示する。

PCでは左側に予約一覧、右側に選択中の予約や候補の詳細を表示する。スマートフォンでは一覧と詳細を縦に並べる。

```text
[RoadRide 配車管理]       [予約一覧] [配車候補] [運行状況]

日付 [        ]  状態 [        ]  [検索]

予約一覧                         詳細
------------------------------------------------
予約番号                        利用者情報
乗車日時                        乗車場所
乗車場所                        目的地
目的地                          マッチング理由
状態                            乗車順
```

対象画面：

- 配車ダッシュボード
- 予約一覧画面
- AI配車候補確認画面
- ルート・乗車順編集画面
- 配車詳細・運行状態更新画面
- 手動配車画面

## 4. デザイン仕様

### 4.1 色

| 用途 | 色 | 用途 |
| --- | --- | --- |
| メインカラー | `#1D4ED8` | 主要ボタン、リンク、選択状態 |
| 成功 | `#15803D` | 予約確定、乗車完了 |
| 注意 | `#B45309` | 待ち時間、確認が必要な状態 |
| エラー | `#B91C1C` | 入力エラー、定員超過、キャンセル |
| 情報 | `#0369A1` | マッチング中、案内メッセージ |
| 本文 | `#172033` | 通常の文章、見出し |
| 補助文字 | `#475569` | 説明文、補足情報 |
| 背景 | `#F8FAFC` | ページ背景 |
| 枠線 | `#CBD5E1` | 入力欄、区切り線 |
| 白 | `#FFFFFF` | パネル、入力欄、カード背景 |

背景色と文字色のコントラストを確保し、状態表示には色と文字を併用する。

### 4.2 文字

- 本文は16px以上とする。
- 見出しは24px前後とする。
- 画面タイトルは28pxを上限の目安とする。
- ボタン文字は16px以上とする。
- 行間は本文で1.6以上とする。
- 文字の詰めすぎを避け、letter-spacingは0とする。

### 4.3 レイアウト

- ページ全体の最大幅は1200pxとする。
- 利用者画面の本文幅は720px以内とする。
- PCでは左右に24px以上の余白を確保する。
- スマートフォンでは左右に16px以上の余白を確保する。
- 入力欄と主要ボタンは画面幅に合わせて伸縮させる。
- 情報カードを二重に入れ子にしない。
- 画面内の主要操作は1つに絞る。

### 4.4 ボタン

| 種類 | 用途 | 例 |
| --- | --- | --- |
| 主要ボタン | 画面の中心となる操作 | 予約を登録、配車を確定 |
| 通常ボタン | 補助操作 | 修正する、候補を再計算 |
| 危険ボタン | 取り消しや削除 | 予約をキャンセル |
| 戻るボタン | 前画面へ戻る | 戻る |

- ボタンの高さは48px以上とする。
- ボタンの文言は動作が分かる日本語にする。
- 重要操作は確認画面を表示してから実行する。
- ボタンを無効化する場合は、理由を近くに表示する。
- スマートフォンではボタンを横並びにしすぎない。

### 4.5 入力欄

- ラベルを入力欄の上に表示する。
- 必須項目には「必須」と表示する。
- 例示が必要な場合はプレースホルダーではなく補足文を使用する。
- エラーは入力欄の直下に表示する。
- 日時、人数、配慮事項には適切なHTML入力要素を使用する。
- 入力エラーがあっても、入力済みの値を消さない。

## 5. 予約状態の表示

| 状態 | 表示名 | 色 | 説明 |
| --- | --- | --- | --- |
| `matching` | マッチング中 | 情報色 | 配車候補を作成・確認中 |
| `confirmed` | 予約確定 | 成功色 | 配車担当者が確定済み |
| `in_progress` | 運行中 | メインカラー | 運行が開始されている |
| `completed` | 乗車完了 | 成功色 | 乗車・運行が完了 |
| `cancelled` | キャンセル | エラー色 | 予約が取り消されている |

状態は、色付きのバッジだけでなく、必ず表示名を記載する。

## 6. 利用者画面の定義

### 6.1 乗車予約画面

表示項目：

- 乗車場所
- 目的地
- 希望乗車日時
- 乗車人数
- 配慮事項

主操作：

- `予約内容を確認`

エラー例：

- 乗車場所を入力してください
- 目的地を入力してください
- 希望乗車日時を入力してください
- 乗車人数は1名以上で入力してください

### 6.2 予約確認画面

入力内容を読み取り専用で表示する。修正と登録を明確に分ける。

主操作：

- `内容を修正`
- `予約を登録`

### 6.3 予約完了・マッチング結果画面

表示項目：

- 予約番号
- 予約状態
- 希望乗車日時
- 乗車場所
- 目的地
- 次に行う操作の案内

### 6.4 予約詳細・キャンセル画面

`confirmed` の場合は、確定した乗車時刻、乗降場所、料金目安、所要時間を表示する。

主操作：

- `予約をキャンセル`
- `予約履歴へ戻る`

### 6.5 予約履歴画面

予約を乗車日時の新しい順に表示する。各行またはカードには予約番号、日時、目的地、状態を表示する。

## 7. 配車担当者画面の定義

### 7.1 配車ダッシュボード

表示項目：

- 本日の予約件数
- マッチング中の件数
- 確認待ちの候補件数
- 運行中の件数
- 乗車完了件数

### 7.2 予約一覧画面

表示項目：

- 予約番号
- 利用者名または識別子
- 乗車人数
- 乗車場所
- 目的地
- 希望乗車日時
- 配慮事項
- 予約状態

絞り込み条件：

- 日付
- 時間帯
- 状態

### 7.3 AI配車候補確認画面

表示項目：

- グループ番号
- 利用者一覧
- 乗車順・降車順
- 出発予定時刻
- 車両と定員
- マッチング理由
- マッチングスコア
- 待ち時間
- 追加所要時間
- 警告・エラー

主操作：

- `候補を編集`
- `手動配車へ切り替え`
- `配車を確定`

### 7.4 ルート・乗車順編集画面

担当者が以下を変更できるようにする。

- 利用者をグループから外す
- 別の候補へ移動する
- 乗車順を変更する
- 降車順を変更する
- 出発時刻を変更する
- 車両を変更する
- 変更理由を入力する

変更後は、定員超過や待ち時間超過を再チェックする。

### 7.5 配車詳細・運行状態更新画面

表示項目：

- グループ番号
- 車両
- 利用者一覧
- 乗車順・降車順
- 出発時刻
- 現在の状態
- 変更履歴

主操作：

- `運行開始`
- `乗車完了`
- `キャンセル`

## 8. 状態別の画面表示

### 読み込み中

- ボタンを連打できない状態にする。
- 「読み込み中」と表示する。
- 既存データがある場合は、可能な範囲で表示を維持する。

### データなし

- 「該当する予約はありません」のように具体的に表示する。
- 次にできる操作があればボタンを表示する。

### 通信エラー

- 「データを取得できませんでした」と表示する。
- `再試行` ボタンを表示する。
- 二重登録を避けるため、送信済みの登録操作を自動で再実行しない。

### 入力エラー

- エラー項目へ移動できるようにする。
- エラー文は日本語で具体的に表示する。
- 送信済みの入力値は保持する。

## 9. レスポンシブ対応

| 画面幅 | レイアウト |
| --- | --- |
| 767px以下 | 1列。予約一覧と詳細を縦に表示 |
| 768px以上 | 予約一覧と詳細を2列で表示 |
| 1200px以上 | 最大幅1200pxで中央寄せ |

スマートフォンでは横スクロールを発生させず、表形式の情報はカードまたは縦積みに切り替える。

## 10. 実装確認項目

- [ ] 全画面でヘッダーと余白のルールが統一されている
- [ ] 本文とボタンの文字が小さすぎない
- [ ] 状態が色と文字の両方で分かる
- [ ] 必須入力とエラー表示が分かる
- [ ] 重要操作に確認画面がある
- [ ] 読み込み中、データなし、通信エラーを表示できる
- [ ] PCとスマートフォンの両方で横スクロールが発生しない
- [ ] 利用者画面は主要操作を3画面以内で完了できる
